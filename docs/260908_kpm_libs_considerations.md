# 260908_kpm_libs_considerations.md — KMP-платформы: звук, воспроизведение MIDI, запись

Документ создан Дисом 2026-09-08 по запросу А.М. («занеси эти платформенные факты в 260908_kpm_libs_considerations.md»). Файл до этого не существовал — создан в `docs/` рядом с родственным `260908_traning_flow_structure_01.md`; если появится версия соседнего агента с тем же именем — требуется слияние.

Контекст: при переносе на Android/iOS (Р1, «перспектива работы на KMP и на не сильно мощной мобилке») у Desktop-приложения есть встроенные механизмы звука в модуле JDK `java.desktop` (AWT/Swing/Java Sound). Вопросы А.М. (2026-09-08): «java.desktop — для андроид как работает? а для iOS? и есть ли в нём запись аудио? или надо встраивать отдельную библиотеку?»

## 1. Платформенные факты (проверено по официальной документации платформ; детали работы на конкретном железе — !ai)

| Платформа | java.desktop | Воспроизведение SMF/MIDI | Запись аудио |
|---|---|---|---|
| Desktop (JVM) | есть (AWT/Swing/Java Sound; Gervill — программный синтез MIDI, банк «Emergency GM», без сэмплов) | `javax.sound.midi` (Sequencer → SoftSynthesizer) — так уже работает `MidiPlayer.kt` | есть: `javax.sound.sampled` (TargetDataLine — захват с микрофона; без сторонних библиотек) |
| Android | нет (ART, java.desktop отсутствует; `javax.sound.midi`/`sampled` нет) | системный `MediaPlayer` — играет MIDI type 0/1 встроенным синтезатором ОС (банк в системе); `android.media.midi` (API 23+) — только транспорт MIDI-событий (устройства), не синтез | системный `AudioRecord` (PCM) / `MediaRecorder` |
| iOS | нет (Kotlin/Native — JVM отсутствует) | `AVAudioSequencer` (AVFoundation) поверх `AVAudioEngine`; обычно требуется свой звуковой банк (DLS/SoundFont) — аналог нашего fluid-soundfont-gm на Linux (!ai — проверить на устройстве) | `AVAudioEngine` → `AVAudioInputNode` / `AVAudioRecorder` |

Вывод: **встраивать сторонние библиотеки не требуется ни на одной платформе** — воспроизведение и запись закрываются системными API через наши `expect/actual`-обёртки в shared (как уже сделано с JNI-транскрипцией).

## 2. Что меняется в архитектуре при переносе

- Desktop-решения (`MidiPlayer.kt`, будущий захват) — JVM-only; в shared остаются только интерфейсы.
- Три actual-слоя под замену: воспроизведение MIDI, запись с микрофона, транскрипция (JNI → libv2m; ORT для Android и iOS существует официально; веса модели ~300 КБ — не проблема).
- Общий GUI-код (shared) при этом не трогается.

## 3. Ядро: файл или поток из памяти? (вопрос А.М., факт по коду)

JNI-вход транскрипции — **поток из памяти**, не файл: `v2m_transcribe(jfloatArray pcm, jint sr, jdoubleArray params)` (v2m_jni.cpp); WAV-разбор делает Kotlin-слой (`readWavMono`, Wav.kt: RIFF/WAVE, PCM 8/16 бит, любое число каналов → моно, float −1..1).

Следствие для записи: захват микрофона → PCM в памяти → транскрипция — **без промежуточного файла**. Файл нужен только для сохранения записи (архив, обучающая пара Р12/Р13).

## 4. Форматы входа (ответ на вопрос А.М. «мы принимаем исключительно wav? другие форматы нет?»)

Факт: вход — только WAV (контейнер RIFF/WAVE), PCM 8/16 бит (GUI), каналы → моно; CLI — тоже WAV. MP3/OGG/FLAC/M4A не принимаются (декодера нет). Расширение входа за пределы WAV — отдельная задача (декодер), в беклог не заносилась.

## 5. Каналы поступления звука в приложение (соображения; для Р14)

Источники, из которых приложение может получить звук:

1. Выбор WAV-файла (есть: [Выбрать WAV], FileDialog).
2. Захват с микрофона (Р14; по умолчанию — системное устройство ввода).
3. Прочие входные устройства: line-in, «монитор» (захват аудио, играющего в системе — транскрипция из любого источника без записи в файл). На Desktop выбор устройства — из списка системных микшеров Java Sound (MixerInfo); на Android/iOS выбор источника — системный (AudioSource/AVAudioSession); конкретика устройства — !ai, уточняется при реализации.
4. Буфер из памяти (уже есть как путь GUI: PCM float → JNI).

Рекомендация: единый внутренний интерфейс «PCM-поток (моно, 22050 Гц) + источник» — все каналы (1–4) сводятся к нему; запись/файл — лишь один из источников.

## OQ-04. Громкость (velocity) — анализ и нормализация

Вопрос: MIDI velocity ограничен 0..127. Требуется анализ кода — возможно, в wav
анализируется самый громкий звук и выполняется своего рода «компрессия».

Предварительный анализ (2026-08-29):
- velocity = amplitude * 127 (midi_notes.cpp:409), где amplitude — средняя энергия
  кадра модели по длительности ноты (не пиковая).
- Нормализации по самому громкому звуку в коде нет: в CLI (src_cli/basicpitch.cpp)
  выполняется только downmix в моно и ресемплинг.
- clamp 0..127 отсутствует: при амплитуде модели > 1.0 velocity превысит 127.
- !ai диапазон значений выхода модели инструментально не проверялся (модель выдаёт
  вероятности, ожидаемо 0..1).

Задача: решить схему громкости (нормализация по максимуму, «компрессия», clamp),
при необходимости вынести ручку.

Дополнение (2026-08-30, А.М.): предполагаемый баг «ритмизация кромсает wav и
транскрипция идёт по изменённому аудио» — **проверен и не подтверждён**: flux
только читает энергию кадров (аудио не модифицируется), транскрипция идёт по
оригинальному wav, квантование не меняет число нот (46/46 на test1.wav).
Однако реальная проблема — неровная динамика голоса при velocity = amplitude×127
без нормализации. Реализована ручка `--velocity-compress <0..1>` (2026-08-30):
v' = 127·(v/127)^(1/k), k = 1+2·сила, + clamp [1..127]. Проверено на test1.wav:
без компрессии velocity 41..114 (ср. 85), с `--velocity-compress 1` — 87..123
(ср. 110); дефолты побайтово идентичны. Статус OQ-04: реализовано.

## OQ-06. Гармонизация распознавания вокала

Соответствует требованию Р2 (docs/brd.md).

Вокал менее точен, чем рояль: вибрато дробит ноту на соседние бины, питч-бенды
уводят от хроматической сетки. Модель выдаёт уже хроматические бины (88 полутонов),
поэтому «гармонизация» — пост-обработка нотных событий (без изменения модели).

Предложенные ручки (отчёт 2026-08-30; реализация отложена):
1. `--harmonize-merge <N>` — объединять соседние во времени фрагменты с разницей
   ≤ N полутонов в одну ноту с доминирующей высотой (убирает «дрожание» вокала).
2. `--min-bend <n>` — отбрасывать питч-бенды мельче n бинов контура
   (1 бин = 1/3 полутона ≈ 33 цента).

### Согласованный алгоритм (2026-08-30, А.М. + сессия)

**Этап 1. Глобальный референс (всегда).** Медиана отклонений сильных/долгих нот
от ближайшего бина (в центах, из питч-бендов) → равномерный сдвиг всех нот
(транспонирование к сетке 440; относительные интервалы сохраняются). Обоснование:
певец уверенно поёт тонику, промежуточные ступени могут «плыть».

**Этап 2. Подбор лада.** На сдвинутых нотах: для каждой тональности/лада (мажор,
минор, натуральный/гармонический/мелодический, дорийский, лидийский) — доля нот,
чей центроид (бин + средний бенд) попадает в ступени (допуск ~30 центов). Лучший
лад ≥ 50% попадания → назначен; финальный снап к ступеням с силой ручки
(0 — только сдвиг этапа 1, 0.9 — «почти», 1 — ровно).

**Этап 3. Фолбэк (ни один лад < 50%).** Предложить пользователю:
(а) оставить только сдвиг этапа 1 (транспонирование, интервалы целы);
(б) не двигать вообще (микротоновый замысел автора).

Оговорки !ai: разрешение оценки офсета ≈ 33 цента (шаг контура); при расстройке
> ~50 центов модель перекидывает ноты в соседние бины — офсет восстанавливать
из картины перекидывания (нужен расстроенный тест).

Статус этапа 1: реализовано 2026-08-30 (`--harmonize-merge`, `--min-bend`,
`--global-shift`; проверено: на test1.wav merge сводит 46→22 ноты; дефолты
байт-идентичны).

Статус этапа 2: реализовано 2026-08-30 (`--mode-snap <0..1>`; src/harmonize.cpp:
`fit_mode` — 12 корней × 6 ладов (мажор, нат./гарм./мел. минор, дорийский,
лидийский), допуск 30 центов, порог ≥ 50%, < 3 нот — фолбэк; `apply_mode_snap` —
целые полутоны в pitch, остаток в bend). Проверено: дефолты байт-идентичны;
test4 (ровный строй) — C major, снап no-op; test1 (вокал) — C major 73%,
притянуты 2 из 22 нот; синтетика (синусы G-A-B-A, +25 центов) с
`--global-shift 1` — лад C major, питчи верные, бенды ≈ +1.3 цента. При
отклонении > ~0.5 полутона от ступени нота перепрыгивает на соседнюю ступень
(при силе 1) — учесть при выборе силы. Два бага реализации найдены и
исправлены: сдвиг питч-классов (A→C, MIDI 24 = C1) и min по подписанному
расстоянию без модуля (все ноты утаскивались вниз на 5-6 полутонов).

**Находка при проверке `--global-shift`:** у контура модели
систематическое смещение ~+1 бин (33 цента) на чистом тоне (440 Гц → бенд +1.0
бина; 435 Гц → +0.425 → расстройка −0.575 бина ≈ −19 центов при факте −19.8 —
механизм относительно точен). Применение сдвига к стройной записи внесёт
~+26..33 цента — нужна калибровка базового смещения контура или порог
(|медиана − бис| > ~0.5 бина). Решение — после расстроенного теста. !ai
(биас может зависеть от материала: на вокале медиана 0.79).

```

- Собрать все выделенные в результате квантизации ноты (без оценки по 88 высотам) 
- выделить наиболее сильные и продолжительные ноты -- выбрать гипотетические основания тональности, найти отклонение (процент) от рядом находящейся стандартной частоты (например, как, Ля=440Гц), сдвинуть все(!) ноты на вычисленное отклонение

- пододвинуть отклонившиеся ноты в нужный тон по 88 высотам (тут нужна "ручка" -- 0 - не двигать, .9 - улучшить "почти в ноты", 1 -- абсолютно в ноты)
```

## OQ-07. Ритмизация (квантизация ритма и детекция темпа)

Задача: вынести темп/TPQN из констант (ручки), детекция темпа и/или квантизация
стартов/концов нот по доле/сетке. Основа для реализации — отчёт о принципах
ритма в docs/history.md (2026-08-30).

### Реализуемый алгоритм (Эллис-подход; согласовано 2026-08-30)

1. **Сигнал силы начал (OSS):** сумма вероятностей onset по всем 88 высотам
   из тензора модели (`InferenceResult.onsets`, кадр 11.6 мс) — OSS(t).
2. **Темп:** автокорреляция OSS по лагам 30–300 BPM; окно-приор — гауссиана
   на лог-шкале BPM с центром 120 BPM (σ = 1.4 октавы) разрешает октавную
   неоднозначность; пик → период P, BPM = 60/P.
3. **Доли (биты):** динамическое программирование (Эллис, 2007): целевая
   функция максимизирует силу onset в долях и штрафует отклонение интервала
   от P; возврат по ссылкам назад — последовательность долей.
4. **Квантизация:** сетка = доли × деление (1/2/4/8); автоматический выбор
   самого мелкого деления, где ≥ 90% начал нот попадают в допуск (~40 мс);
   старты/концы прижимаются к сетке; в MIDI пишется вычисленный BPM,
   TPQN 480 (делится на 2..16; 220 — только на 4).
5. **Фолбэки:** < 5 начал или нет стабильного пика → ритм «сырой» + ручной
   `--tempo`. Слабое место метода — вокал (размытые атаки); OSS из модели
   проверяется эмпирически. !ai

Ручки: `--tempo <BPM>` (ручной; 0 = авто), `--quantize <auto|off|beat|eighth|sixteenth>`
(по умолчанию off — поведение без изменений), `--tempo-tolerance <мс>` (40).

Лицензии: метод — по статье (свободно); эталон — librosa (ISC); своя C++
реализация, новых зависимостей нет.

Статус: реализовано 2026-08-30 (src/rhythm.cpp; опции `--tempo`, `--quantize`,
`--tempo-tolerance`; дефолты побайтово идентичны; авто на test1.wav: 120.2 BPM,
46/46 нот на сетке, отклонение ≤ 30 мс).

Дополнение (детекция размера, 2026-08-30): сигнал акцентов — аудио flux,
sqrt-компрессия (экспандирование проверено — не помогло), одна рамка = одна
доля, детрендинг окном 12 (края делятся на 12), последняя неполная доля
отбрасывается; кандидаты {3, 4} с маргином ≥ 2%, порог ≥ 24 доли, иначе фолбэк
4/4. Результат: test3.wav (вальс) — 3/4; вокал и короткие клипы — фолбэк 4/4.
Желательно: ручная опция `--time-signature NN/DD` для контроля (не реализована).

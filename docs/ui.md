# v2m — Описание пользовательского интерфейса

Фактическое описание GUI приложения v2m (аудио → MIDI-транскрипция), версия — билд #40 (2026-09-09). Назначение: единый справочник для агентов (анализ, ревью, проектирование изменений). Стек: Kotlin, Compose Multiplatform Desktop, Material 2 (`MaterialTheme.colors`, не M3); один язык интерфейса — русский; все строки — `object Strings` (Strings.kt) — менять только там. Источник правды кода — `app/desktopApp/src/desktopMain/kotlin/com/v2m/app/` (интерфейс desktop) и `app/shared/src/` (общий код: `commonMain` — модели и строки, `jvmShared` — файлы, prefs, JNI; 2026-09-22).

## 1. Файлы модуля UI

| Файл | Роль |
|---|---|
| `App.kt` | корневая `@Composable App()`: всё состояние, фреймы, меню, диалоги, обработчики, панель правки нот (EditNotePanel) |
| `NoteChart.kt` | гистограмма «высота × время» (канва, скролл, хит-тест, разметка ступеней, рамки muted/selected) |
| `Strings.kt` (shared) | все пользовательские строки + `HELP` (long-press справки) |
| `Preferences.kt` (shared) | `prefs.properties` в каталоге данных (`AppData`: desktop `~/.v2m`, Android `filesDir`); загрузка/сохранение, атомарная запись через tmp |
| `Presets.kt` (shared) | пресеты: фабричные (ресурс `composeResources/files/presets.json`) + пользовательские (`presets.properties` в каталоге данных) |
| `Key.kt` (shared) | тональности: `keyFromSelection(0..24)`, `parseKeyFromReport`, `noteLabel`, `harmonyPct` |
| `NoteEdit.kt` (shared) | правка высоты ноты в MIDI-потоке (`retuneNoteMidi`: сдвиг NoteOn/Off + выброс бендов канала) |
| `AbcExport.kt` (shared) | экспорт текущей версии в текст abc (`exportAbc`) |
| `MidiPlayer.kt` (desktopApp), `Instruments.kt`, `Midi.kt`, `MidiMeta.kt` (shared) | воспроизведение (встроенное; на Android — `MediaPlayer`, этап 5), GM-инструменты, парсинг MIDI, экспорт-мета |
| `NativeCapture.kt` (desktopApp) | захват с микрофона (ALSA через JNI → моно PCM 22050; фазы `RecPhase`, остановка close()-ом). На Android — `AudioRecord` (этап 5) |
| `Level.kt` | полоса-индикатор уровня: `AudioLevel` (mic/midi), `meterZoneColor` (зоны), `meterFill` (заливка) |
| `Wav.kt`, `V2mEngine.kt` (shared) | чтение PCM, транскрипция через JNI → libv2m |
| `Log.kt` (shared) | `Log.d(tag, msg)` — журнал в `v2m-debug.log` каталога данных (append), метки `[tap]`/`[tone]`/`[abc]`, время HH:mm:ss.SSS; `DEBUG=true` в debug-сборке |

## 2. Макет окна

Вертикальная колонка (вся — `verticalScroll`), под ней — закреплённый низ ([Транскрипт] [▶ растянута] [Экспорт] — билд #36, п.2; имя формата с кнопки убрано в #38 — выбор типом в диалоге). Справа сверху — плавающая кнопка-«сэндвич» (☰), поверх контента. Порядок сверху вниз:

```
┌───────────────────────────────────────────────────────────┐
│ ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓ (0.9 ширины)   │
│                      полоса уровня (билд #40)            │
│ [Выбрать WAV] [●] ⏱0:00 имя.wav [Сохранить]  …(☰-кнопка) │
│ Пресет: [Открыть ▾] [поле имени───] [Сохранить]           │
│ ▾ Обработка (свёртываемый фрейм; билд #50)                 │
│ ▾ Ритмика  (свёртываемый фрейм)                           │
│ ▾ Мелодика  (свёртываемый фрейм)                           │
│ ошибка (красный текст, если есть)                          │
│ ▾ Версии   (список радио-версий)                           │
│ ▸ Отчёт    (свёрнут по умолчанию)                          │
│ ▾ Звучание (вкладки Спектр|Кванты|Тоны|ABC; под «Тонами» —│
│             панель правки [<][>][X], см. §10)              │
│ ▾ Экспорт  (темп/размер/ключ/затакт/инструмент)           │
├───────────────────────────────────────────────────────────┤
│ [Транскрипт] [─────────▶─────────] [Экспорт]      (низ)   │
└───────────────────────────────────────────────────────────┘
```

Свёртываемые фреймы (▾/▸: «Обработка», «Ритмика», «Мелодика», «Версии», «Отчёт», «Звучание», «Экспорт») помнят своё состояние в prefs (билд #52, п.6 приёмки #51) — ключи `section.<id>`; фрейм без записи открывается по своему дефолту («Отчёт» — свёрнут).

Низ (билд #36, п.2): три кнопки на всю ширину — [Транскрипт] (при busy —
спиннер 14 dp внутри, слева от текста «Идёт обработка...»), посредине
[▶] — `OutlinedButton` (рамка), `weight(1f)`, высота 48 dp (п.2, дословно:
«Play — растягивается, заполняя среднее пространство»), справа
[Экспорт] (без имени формата — билд #38, замечание «г») → системный
диалог сохранения (§13).

Поведенческие детали макета:
- Фреймы (кроме «Отчёта») открыты по умолчанию; заголовок — `TextButton` с `▾/▸`; контент — `AnimatedVisibility`.
- Между фреймами «Обработка» и «Ритмика», а также «Ритмика» и «Мелодика» — `Divider()`.
- Ошибки (`error: String?`) — текст `MaterialTheme.colors.error` под «Мелодикой».
- Полоса уровня записи-воспроизведения (билд #40): отдельная строка над шапкой — шапка опущена вниз на высоту полосы 12 dp + зазор 6 dp. Полоса шириной 0.9 окна (`fillMaxWidth(0.9f)`), по центру, высота 12 dp, скругление 6 dp. Вид — заливка слева по уровню, цвет по зоне (вариант согласован с А.М. 2026-09-09); в «молчании» полоса пуста — невидима (место резервируется). Зоны (по RMS в dBFS, Level.kt `meterZoneColor`): < −42 дБ — пусто; серый до −30; салатовый до −12; малиновый выше (пороги калибруются на слух — константы в Level.kt). Источник уровня по режиму: запись (`RecPhase.Recording`) — реальный RMS блоков сэмплов микрофона (`NativeCapture` публикует `AudioLevel.mic`); воспроизведение — «громкость нот» MIDI: сумма velocity звучащих нот, прозрачный `MeterReceiver` между Sequencer и Synthesizer (`AudioLevel.midi`, полная шкала = 4 ноты fff; реальный сигнал синтезатора не измеряется — решение А.М. 2026-09-09). Сглаживание VU: подъём быстрый (k = 0.45), спад медленный (k = 0.08), цикл 40 мс → `meterLevel`. Аттенюатор MIDI (билд #51, Р17 п.4) полосу не меняет: она показывает velocity нот, а не уровень синтезатора. Ограничение: внешний MIDI-плеер (☰ «Слушать» → «внешний MIDI-плеер») звучит вне приложения — уровень не измеряется, полоса гаснет.
- Шапка (Р14, билды #38/#40): ряд `[Выбрать WAV] [●] ⏱таймер <имя> [Сохранить]`.
  - `[Выбрать WAV]` — `Button(Strings.wavButton)`; выбор — системный AWT `FileDialog` (LOAD), стартует в `lastWavDir`. Имя файла (или `Strings.noFile`) — справа от таймера (вес 1f, перенос не нужен); выбор нового файла отменяет непосохранённую запись. Диалог «Сохранить?», если запись не сохранена (билд #56, Р14 п.7), — **до** открытия FileDialog, сразу по нажатию (билд #57, п.2а приёмки #56: прежде файл выбирался, а затем действие отменялось вместе с выбором).
  - Таймер (билд #40) — семисегментный дисплей `SevenSegDisplay` справа от кнопки записи: поле 88×38 dp (билд #49: высота — как у кнопок ряда, `CtrlHeight` 38 dp; сегменты крупнее), тёмный фон, красные сегменты (Canvas: 7 сегментов на ячейку, круглые концы, маски SEG7; внешних шрифтов нет). Формат «m:ss», ячейка знака слева резервируется (цифры не прыгают), двоеточие — две точки между минутами и секундами. Содержимое по фазе `recPhase`: Countdown — «-0:01»..«-0:00», отсчёт 2 с (билд #56, Р14 п.2); Recording — «0:00»..«1:00» — счёт вверх каждую секунду, автостоп на 1:00; Idle — длительность последней записи («m:ss») тусклым (alpha 0.3), «0:00», если записи не было.
  - `[●]` — кнопка записи (Р14): красный кружок 18 dp на кнопке (`CircleShape`), три фазы `RecPhase`:
    - Idle — подпись «Записать с микрофона» (`recCd`), кружок не мигает;
    - Countdown (после нажатия) — отсчёт 2 с: «-0:01», «-0:00» в таймере (цифра из кружка убрана — билд #40; длительность 2 с — билд #56, Р14 п.2), подпись «Запуск записи через N… (нажмите — отменить)», на последней секунде (цифра 0) — «Запуск записи… (нажмите — отменить)»: это момент старта, после которого счёт идёт от «0:00» вверх; повторное нажатие отменяет (фаза → Idle); перед отсчётом — диалог «Сохранить?», если запись не сохранена (билд #56, Р14 п.7);
    - Recording — подпись «Остановить запись», кружок мигает (alpha 1→0.25, 400 мс, Reverse); нажатие — остановка захвата (фикс стопа, билд #40: `line.close()` пробуждает блокирующий `read()`, данные до стопа сохраняются).
    Запись: `MicCapture` (22050/16/моно — параметры модели; при неспособности устройства — 44100/48000 + линейный ресемплинг) в фоновом потоке, автостоп 60 с. Завершение: автоимя `rec_ГГГГММДД_ЧЧММСС.wav` по времени старта, запись — текущий вход транскрипции (без промежуточного файла: ядро принимает PCM из памяти).
  - `[Сохранить]` — `Button(saveLabel)`, активна только для свежей (несохранённой) записи: системный диалог «Сохранить как» (JFileChooser, фильтр `.wav`, автоимя — стартовое имя файла, каталог — `lastWavDir`); после сохранения имя в шапке меняется на сохранённое. Существующий файл не перезаписывается молча (билд #57, п.2б приёмки #56): подтверждение «Заменить?» — «Заменить» (записать), «Другое имя» (вернуться к выбору файла; диалог переиспользуется — навигация сохраняется), «Отмена» (сохранение отменить). Проверка своя, а не диалога: дописанное «.wav» встроенный диалог не видит (проверено по JDK 21 — в Swing-диалоге проверки перезаписи нет).
  - Диалог «Сохранить?» (билд #56, Р14 п.7) — `confirmUnsavedRecording()`: `JOptionPane` с заголовком «Запись не сохранена», вызывается перед `[●]` в фазе Idle и перед `[Выбрать WAV]`, если `rec != null && !recSaved`. Исходы: «Сохранить» → `saveRecording()`, действие продолжается только при успешном сохранении (отмена в системном диалоге отменяет и действие); «Не сохранять» → действие продолжается без сохранения; «Отмена» (и закрытие диалога) → действие отменяется. Запись, сохранённая в файл, диалога не вызывает. Тот же диалог вызывается при закрытии окна приложения (билд #57, п.2в приёмки #56: колбэк `CloseGuard.confirm` из `App()` → `Window.onCloseRequest` в Main.kt; окно закрывается только при «Не сохранять»/успешном сохранении, повторный запрос закрытия во время диалога игнорируется — `CloseGuard.inProgress`).

Персистентность: `savePrefs()` — при каждом изменении (`LaunchedEffect(params, keySel, smoothingWindow, instrument, clef, anacrusis, listenExternal, darkTheme, showAbc, notesTab, gamma, exportFmt, author, tScale, pitchLo, pitchHi)`), при выходе (`DisposableEffect`), после каждого действия (выбор файла, транскрипция, сохранение) и в `applyPreset`/`savePreset` (имя пресета — сразу в prefs).

`Version` (одна строка истории): `midi: ByteArray`, `notes: List<MidiNote>` (разобранные), `report: String` (отчёт движка), `wavName`, `params`, `muted: Set<Long>` (заглушённые кнопкой [X] ноты — ключи `noteKeyOf(startTick, pitch)`), `framesJson: String` — сводка кадровых признаков, извлекается из ядра при каждом прогоне (билд #38: всегда; файл пишется только при экспорте типом «.mid + признаки»), и опционально «Вход»: `midiIn/notesIn/reportIn` — повторный прогон с нейтральной мелодикой (нужен, когда мелодические параметры не нейтральны; `melodyNeutral()` проверяет — с билда #54 и «Сглаживание», и «Стабильность питча» равны «выкл»). `notesForInput/reportForInput` — для показа вкладки «Кванты». `spec: Spectrogram?` (билды #47/#48) — спектрограмма RAW-материала для вкладки «Спектр»: версия лишь запоминает готовую (`inputSpec` материала на момент прогона; считает её `computeSpectrogram` — по сырому аудио, при выборе файла/записи; в прогонах «Вход» не участвует); `specOut: Spectrogram?` (билд #50) — спектрограмма материала **после** эффектов «Обработки» (тем же вызовом, что идёт в модель: `V2mEngine.processAudio` → `spectrogram`), показывается на вкладке «Спектр» по умолчанию. Правки нот изменяют текущую версию (новая `Version` с правками и тем же номером); отмены нет.

## 4. Пресеты (строка «Пресет:»)

## 7. Фрейм «Версии» (Strings.secVersions)

`LazyColumn` (max 96 dp) радио-строк, версии сверху-вниз: индекс `idx = size−1−i`. Формат строки (`Strings.versionRow`):

## 9. Фрейм «Звучание» (Strings.secNotes) — вкладки Спектр | Кванты | Тоны | ABC

Вкладки — ряд контурных `OutlinedButton` (билд #49, высота по контенту): активная — акцентная рамка и текст (как у кнопки PLAY), неактивные — приглушённый контур (`onSurface` 0.3 рамка / 0.6 текст); до #49 — Material `TabRow`/`Tab` (заливка «зацеплялась за тёмную тему»). Вкладки видны и без результата (билд #48): «Спектр» работает всегда, прочие при отсутствии версии/разобранного MIDI показывают `(результатов нет)` / `(не удалось разобрать MIDI)`. Имена вкладок — `tabSound` «Спектр» (билд #47 — первая, «Звук»; переименована билдом #49), `tabInput` «Кванты», `tabOutput` «Тоны» (бывшие «Вход»/«Выход», билд #35), `tabAbc` «ABC». Активная вкладка — из prefs (билд #48). Вкладка «ABC» показывается при `showAbc` (☰ «Вид» → «ABC-notation»); скрытие активной «ABC» переключает на «Тоны». Смена вкладки сбрасывает `selectedKey`.

- **Спектр** (билды #47/#48, имя — #49, RAW-переключение — #50) — `SpectrogramView(s, tScale, playPosSec, gamma, invert = !darkTheme, holdSpec, holdLabel, notesEndSec = v?.notes?.maxOfOrNull { it.endSec } ?: -1f)`, где `s = v?.specOut ?: sRaw`, `sRaw = v?.spec ?: inputSpec`, `holdSpec = sRaw.takeIf { it !== s }` — п.1/п.2 приёмки #48: гамма из `prefs.gamma` (☰ «Гистограмма» → «Гамма»), в дневной теме палитра инвертируется (255−v по каналам). Материал канвы — **после** эффектов «Обработки» (билд #50, Р16 п.7): версия хранит `specOut` — спектрограмму того материала, что пошёл в модель; пока канва нажата, показывается RAW-материал (данные п.0 модели А.М.) с меткой «RAW» в углу видимого окна, при отпускании — снова обработанный (`holdSpec` = null, если они совпадают — жест не ставится). Спектрограмма RAW считается сразу при выборе WAV или по окончании записи (билд #48, `computeSpectrogram`, в фоне) и не меняется при вращении ручек; пока идёт расчёт — `(расчёт спектрограммы…)`, если материала нет — `(результатов нет)`. Построение — multi-resolution STFT (окна 256/1024/4096, hop 256; 120 лог-полос 10 Гц..10 кГц). Оси как у гистограммы: время вертикально (кадр 0 сверху), частота горизонтально (логарифмическая сетка с метками 100/1k/10k). Палитра — одна из 4 гамм (`Gamma`, билд #56 — новый набор и порядок): «Монохром» (`monochrome` — билд #51 вместо «Инферно», билд #52 — нейтральный: равные серые от (0, 0, 0) до (255, 255, 255), R = G = B), «Магма» (`magma`, гамма по умолчанию — палитра билда #47 без изменений, узлы 0.20 шагом), «Зима-Блю» (`winter-blue` — от чёрно-синего к белому через голубой), «Гольф» (`golf` — от чёрно-зелёного к белому через травяной; билд #57, п.3 приёмки #56: переименована из «Тропика», цвета без изменений); у всех, кроме «Магмы», узлы 0.00/0.16/0.36/0.64/0.84/1.00 (края контрастнее, средняя область шире), интерполяция в RGB, 256 цветов; 0 = тишина … 255 = верх. Прежние id из prefs ведут на свои гаммы: `inferno` → «Монохром», `plasma` → «Зима-Блю», `viridis`/`tropic` → «Гольф». Граница «конец нот» (билд #56, OQ-25): штриховая линия цвета `secondary` на времени `notesEndSec` с плашкой «конец нот» — правее звучания нот нет; едет с содержимым канвы, без прогона не рисуется. Шкала адаптивная (верх — 99.5-й процентиль, диапазон 60 дБ, наклон +3 дБ/окт). При выборе версии показывается её спектрограмма, а если расчёт к моменту прогона не успел — текущий материал. Прокрутка и автоскролл за полоской позиции — как у `NoteChart`; жест нажатия события не поглощает (`awaitFirstDown(requireUnconsumed = false)`, без `consume`), поэтому прокрутка канвы продолжает работать. Правки нот канву не затрагивают.
- **Кванты** — гистограмма `NoteChart(notesForInput, key = parseKeyFromReport(reportForInput), tScale, onNoteClick = { звук тона })`. Клик звучит, выделения нет.
- **Тоны** — `NoteChart(notes, effectiveKey, tScale, mutedKeys = v.muted, selectedKey, onNoteClick)`: клик по столбику — выделение (постоянная рамка) + звук тона (кроме заглушённых); ниже — панель правки (§10). См. §12.
- **ABC** — текстовая таблица строк-нот (моноширинная, SelectionContainer, LazyColumn max 300 dp): шапка `  такт:доля | нота·длит. | длит.с  | громк.`, строки `  %1s%02d:%s | %s | %7.2f | %3s` (тильда `~` = не на сетке — поле фиксированной ширины; такт/доля по эффективному размеру `finalSizeOverride ?: обнаруженный`; ячейка — `нота·длит.` через `noteCell(pitch, isRest, durationQuarters, key)`; `~` в ячейке означает лигу/продолжение, `z` — пауза; громкость пуста у пауз). Ключ разметки ячеек — `effectiveKey`. Таблица собирается при активации вкладки — скрытая вкладка не перерисовывается.
- Нажатие на строку ноты (не паузы) — `playNoteTone(pitch, velocity)` с начала нажатия + `Log.d("abc", …)`. SelectionContainer перехватывает down/up в Main-пассе, поэтому обработка — в Initial-пассе (`awaitFirstDown(pass = Initial)`, подсветка строки заливкой primary alpha 0.15 на время нажатия, цикл до отпускания); `clickable`/ripple не работает под SelectionContainer (билд #35, п.1).
- **Заглушённые ноты** (`v.muted`, см. §10 п. 4): в «Тонах» — контурная полоска вместо заливки (клик по контуру ±4 px не выделяет и не звучит); в ABC — ячейка `noteLabel(pitch, key) + "×"` (например «C4×», «^C4×» — «×» на месте множителя длительности), длительность 0.00 с, громкость пуста; строка не звучит и не озвучивается.

## 10. Панель правки ноты под «Тонами» (билд #35, п.4)

`EditNotePanel(notes, selectedKey, muted, onDelta, onMute)` — Row под гистограммой «Тоны» (под «Квантами» и «ABC» панели нет). Состав:

- Текст информации: без выделения — `editNoSelection` («нота не выбрана: кликните по столбику»); при выделении — имя выбранной ноты: `sel.name` (например «C4») + `centsText`: «+32%»/«−40%» (проценты полутона); у чистых нот (`|cents| < 0.5`) текст пуст. Нота с микротоном — третий полутон: `bendInRange`-парсер даёт `cents` (bend канала 0 на интервале ноты).
- Кнопки: `[<]` (`editDownCd`: вниз на полтона), `[>]` (`editUpCd`: вверх), `[X]` (`editMuteCd`: удалить/вернуть). Без выделения — все disabled (содержание кнопок — символы; назначение — в contentDescription).
- Семантика [<]/[>] при микротоне: первое нажатие убирает сдвиг к чистой ноте в сторону шага — «C+32%»: [<] → C, [>] → C#; дальше шаги хроматические (у чистой ноты первым нажатием микротон накапливается: [>] → C+50%). Правка: `editNote(v, delta)` → `retuneNoteMidi` сдвигает NoteOn/Off ноты (clamp 0..127) и выбрасывает бенды канала на её интервале; нота пересоздаётся (возвращается исходная, если правок не было), звучит тоном новой высоты (не звучит, если нота заглушена), гистограмма и ABC перерисовываются, `selectedKey` обновляется (рамка сохраняется).
- [X] — кнопка с памятью: заглушенная нота — `muted`-набор содержит `noteKeyOf(startTick, pitch)`; X залита (нажатое состояние), нота с нулевой длительностью: не звучит (клик/правка/«Слушать»/экспорт — фильтр `normalizeMidi(midi, muted)`), на гистограмме контурная полоска (Stroke 1 dp — «рамка вокруг нуля», клик ±4 px), в ABC — строка с «×», 0.00 с, без громкости. Повторное нажатие убирает ключ — длительность возвращается. Правка высоты заглушённой ноты переносит mute-ключ на новую высоту.

Встроенный редактор значений — `InlineField` (BasicTextField, без рамки, одна подчёркивающая линия; валидация «пусто/только допустимые цифры», невалидный ввод игнорируется, число можно стереть и ввести заново).

## 12. Гистограмма NoteChart (детали для работы с ней)

- **Геометрия**: Y — время вниз; X — питч. `lowPitch = min(pitch) − 3` (самая нижняя нота минус 3 полутона) — левый край канвы; один полутон = слот шириной `slotW = width / nSlots`. Столбик ноты залит от x=0 до **частоты ноты** `xRight = slotW·(pitch + cents/100 − lowPitch)` (билд #36, п.1: «окончание столбика означает частоту ноты»): нота на ступени (cents ≈ 0) ровно дотягивается до её линии и соприкасается, микротон — доля слота за ней — **горизонтальная протяжённость столбика и есть питч ноты** (раньше: правый край слота — чистая нота заходила за линию ступени на слот). Высота окна 300 dp; `dpPerSec = 300/tScale`; канва высотой `effDur·dpPerSec` (`effDur = max(duration, tScale)`), при длинной записи — вертикальный скролл.
- **Отрисовка**: разметка ступеней I/IV/V (вертикальные линии по слотам питча с тоникой `key.rootPc`, жирнее/темнее I) — под столбиками; столбики — `drawRect` high→low (низшая рисуется поверх; нижняя нота не закрывает хвост верхней). Прозрачность столбика = громкость ноты (линейно 0.25..0.95 по velocity). Играющая нота обведена рамкой цвета primary 2 dp (200 мс, повторный клик продлевает). Заглушённая нота (`mutedKeys`) — вместо заливки контурная полоска Stroke 1 dp по форме столбика («рамка вокруг нуля»). Выделенная нота (`selectedKey`, только в «Тонах») — постоянная рамка accent 2 dp **поверх** всех столбиков.
- **Хит-тест** — на скролл-контейнере: координаты клика уже в content-пространстве (включают скролл) → `t = y / pxPerSec` (без повторного прибавления scroll!). Попадание — по **заливке**: `t ∈ [startSec, endSec)` и `x ≤ xRight` (та же граница частоты, что и у отрисовки); у заглушённых — по контуру полоски (±4 px); из покрывающих звучит **низшая по питчу** (minBy pitch) — видимая в точке (отрисовка high→low). Звук — на нажатии (`awaitFirstDown`), не на отпускании. Клик по заглушённой ноте звука не даёт (журнал `[tap] … (заглушена)`). Клик мимо заливок — только запись в журнал, без звука. Пока `Log.DEBUG`: строка `[tap] x=… y=… scroll=… t=… → нота p=… v=… start=… длит=… клик: N% от макушки столбика` (0 % = верхняя кромка).
- **Тон клика**: `playNoteTone(pitch, velocity, cents)` → мини-SMF (1/8 с, 120 BPM, инструмент = выбранный в «Экспорте», громкость = velocity ноты, микротон — питч-бендом канала 0 на весь тон). Тон заменяет текущее воспроизведение. Клик в «Тонах» дополнительно выделяет ноту (`selectedKey`, §10); в «Квантах» и ABC — только звук.

## 13. Низ окна и ☰-меню

- Низ (вне скролла; билд #36, п.2) — три кнопки на всю ширину ряда (spacedBy 8): `[Транскрипт]` (enabled при wavFile и !busy; при busy — спиннер 14 dp внутри слева + текст «Идёт обработка...»), посредине — кнопка-«Слушать»: `OutlinedButton` с рамкой (п.2: «ей надо рамку»), растянута `Modifier.weight(1f)`, высота 48 dp (была 36 dp — SoundButton задавал `.size(36.dp)` после модификатора вызова и перекрывал его), иконка Play/Stop по центру (cd `listenIconCd`/`stopIconCd`; enabled при !busy и versions непуст); справа `[Экспорт]` — `Button` с текстом только `exportLabel` (имя формата на кнопку не выводится — билд #38, замечание «г»; имя текущего типа — в contentDescription `exportCd`), enabled при !busy и versions непуст. Меню форматов и busy-спиннер в ряду удалены.
- Экспорт (билд #36, п.3; типы — билд #38, замечание «в») — системный диалог: `JFileChooser` (Swing), заголовок «Сохранить как», `isAcceptAllFileFilterUsed = false`, фильтры типов `FileNameExtensionFilter` (имена — `Strings.EXPORT_FMT_NAMES`): `.mid`, `.mid + признаки (.frames.json)`, `.musicxml`, `.abc`; стартовый фильтр — `exportFmt` (persist); стартовое имя — имя исходного wav; каталог старта — каталог последнего сохранения. После APPROVE: тип = выбранный фильтр → `exportFmt = fmt` (persist); имя без точки → дописывается расширение типа; каталог запоминается (`lastMidiDir/lastXmlDir`); запись `exportVersion(v)`: `.mid`/`.mid + признаки` — `midiWithMetaTrack` (muted-фильтр, JSON параметров); тип `.mid + признаки` дополнительно пишет рядом `<имя>.frames.json` из `Version.framesJson` — сводка извлекается из ядра при каждом прогоне (флажка в UI нет), `meta.track` — имя wav, `meta.author` — из ☰-меню (пусто — не пишется), `meta.ts` — время прогона (ставит движок), `.musicxml` — `midiToMusicXml` (clef/fifths/затакт), `.abc` — `exportAbc`; неуспех — `error`.
- Транскрипция (async, Dispatchers.Default): читает WAV → «Вход»-прогон (если мелодика не нейтральна) → основной прогон → парсит MIDI → обновляет автодетект темпа/размера → добавляет `Version` и выбирает её; сбрасывает `selectedKey`. Ошибки — в `error` (и stderr движка — отдельно).
- «Слушать»: MIDI = `exportMidi(v.midi, effectiveKey, v.muted)` — заглушённые ноты не звучат. Встроенный плеер (`listenExternal=false`): повторное нажатие останавливает. Внешний (`true`): temp-файл `~/.v2m/v2m-listen.mid` + `Desktop.open`.
- **☰-меню** (правый верхний угол, панель шириной 2/3 окна, клик-ловушка на весь экран закрывает): секции «Слушать» (чек «внешний MIDI-плеер»; слайдер «Громкость MIDI: N %» — 0..127, билд #51, Р17: CC7 всех каналов встроенного плеера, 100 = заводская громкость синтезатора, при внешнем плеере слайдер неактивен, prefs `midiVolume`; слайдер «Громкость WAV: N %» — регистр 0..100 = 0..25 % усиления, дефолт 100, билды #52/#53, Р18: линейный множитель к сэмплам ▶ источника, действует и на звучащее воспроизведение, prefs `wavVolume`; поясняющие подписи под обоими движками убраны билдом #53 по приёмке #52), «Вид» (чек «тёмная тема», чек «ABC-notation» — показ вкладки «ABC», prefs `showAbc`; при снятии активной «ABC» — переключение на «Тоны»), «Файл признаков» (билд #38, замечание «б»): пункт «Автор: %s» — имя автора или «не указан» → AlertDialog «Автор файла признаков» с текстовым полем ([OK]/[Отмена]); имя персистится (`prefs.author`) и попадает в `meta.author` файла признаков; пусто — поле не указывается), «Гистограмма» (слайдер «t-масштаб: %.1f с», 1..10; RangeSlider «диапазон нот»; пункт «Гамма: <название>» — билд #49: AlertDialog выбора из 4 гамм с образцом шкалы, `prefs.gamma`), пункты «О программе» (билд #N, о программе, разработчик attplus.in, ссылка http://attplus.in/v2m — страница приложения без SSL, билд #58; в браузере — Desktop API, при его отсутствии xdg-open, билд #57), «Конфиденциальность», «OSS credits» — AlertDialog с текстом и [Закрыть]. ## 14. Действия, общие для всех элементов

- Любое изменение параметров — мгновенное переприменение в состояние; повторная транскрипция — только кнопкой «Транскрипт».
- Тема: Material 2 `darkColors()/lightColors()`; текст на `onBackground` (InlineField красит явно — дефолт чёрный, на тёмной теме невидим). Иконки — SVG в `composeResources/drawable` (заливка #1f1f1f; play.svg/stop.svg для кнопки-«Слушать»), тонируются темой.
- Отмена/восстановление: **отсутствует**; undo отсутствует. Правки нот (§10) необратимы — изменяют текущую версию (перезапись результата; повторная транскрипция исходника даёт прежний результат).
- Все тексты — русские; всплывающая справка — long-press на подписи.
- Журнал `[tap]/[tone]/[abc]` идёт в `~/.v2m/v2m-debug.log` — единственное место отладки взаимодействий; сессии разделяются строкой `=== v2m #<BUILD>: журнал тестирования ===`.

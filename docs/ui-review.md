# v2m — Ревизия стиля UI и проектирование «корректировки нот»

Дизайн-документ по запросу А.М. 2026-09-06. Вход: фактическое описание UI (docs/ui.md, билд #34). Статус: предложения к обсуждению, в brd.md не внесено.

## а) Общий стиль приложения — замечания и рекомендации

### Замечания (по документальному факту, без оценок «плохо/хорошо»)

1. **Смешение тулкитов диалогов**: выбор файлов — системный AWT `FileDialog`, остальное — Compose (`AlertDialog`, `DropdownMenu`). Разные внешний вид и поведение (модальность, фокус).
2. **Один длинный вертикальный скролл**: 6 свёртываемых фреймов в колонке; «Звучание» и «Экспорт» — за линией сгиба; после транскрипции пользователь сам ищет результат.
3. **Гистограмма — единственный графический элемент**; остальной UI — плотные текстовые строки (подписи + слайдеры). Канва-графика (NoteChart) и контролы живут в разных визуальных языках.
4. **Справка — только long-press на подписи**: обнаружимость низкая (жест не анонсирован нигде).
5. **Клавиатуры нет**: ни горячих клавиш, ни фокус-навигации — только мышь. Десктоп-приложение.
6. **Ошибки — красной строкой в потоке**, без dismiss и без звука/диалога; невалидный ввод полей молча игнорируется (фидбэка нет — намеренно, но непоследовательно: часть ограничений видна только в поведении).
7. **Семантическая перегрузка «Слушать»**: кнопка низа (воспроизведение/остановка) и заголовок секции ☰-меню (выбор плеера).
8. **Регистр и пунктуация строк смешаны**: кнопки-действия с заглавной («Транскрипт», «Слушать», «Выбрать WAV»), статусы/ошибки — строчные без точки («(результатов нет)»); внутри фреймов — «Квантизация: off» (английские значения в русском UI).
9. **Нет undo/redo и нет подтверждений** — приемлемо, пока действия обратимы выбором версии; при появлении необратимых действий (правка нот) потребуется явная модель отката.
10. **Иконки** — три SVG-кнопки (☰, ♩, ♪), остальные действия — текст; визуальная иерархия действий держится только на Material-кнопках.
11. Строка версии перегружена (`В.%02d — 4/4, 120.0 BPM, 40 нот, C major, 91% гарм., имя.wav`) — читается как единый текст, а не как колонки.

### Рекомендации (дешёвые, в стиле текущей архитектуры)

1. **Авто-прокрутка к «Звучанию»** после завершения транскрипции (`scrollState.animateScrollTo`) — результат появляется перед глазами без поиска. Отменить — повторным скроллом (тривиально).
2. **Горячие клавиши**: Enter — «Транскрипт», Space — «Слушать/Остановить», Ctrl+O — «Выбрать WAV» (Desktop-привычки; в Compose Desktop — `Modifier.onPreviewKeyEvent` на корне). ~15 строк.
3. **Единый стиль сообщений**: зафиксировать правила в Strings.kt (статусы строчные без точки; ошибки — с точкой; значения параметров — русские там, где есть слова: off→«выкл» и т.п. — QUANTIZE_OPTIONS уже смешан). Косметика, точечно.
4. **Разовый анонс long-press справки**: строка-подсказка внизу («зажмите название параметра — справка») или тултип на первом запуске; дальше — тултипы по ходу.
5. **Dismiss ошибки**: крестик/клик по строке ошибки (клик = сброс `error`), т.к. строка не исчезает сама.
6. **Переименовать секцию меню «Слушать» → «Воспроизведение»** (в меню останется чек «внешний MIDI-плеер»); кнопка низа остаётся «Слушать».
7. **Подписи разделов и пунктуацию** привести к одному шаблону в Strings.kt — не переписывая логику.
8. Всё остальное (Material 2, темы, InlineField, Collapsible-фреймы, AWT FileDialog) — **сознательно оставить**: работающая, проверенная приёмками база; миграция (M3, собственные диалоги) — отдельный проект, не сейчас.

## б) «Пользовательская корректировка нот» — варианты

### Общие архитектурные опоры (для всех вариантов)

- **Что уже есть бесплатно**: хит-тест гистограммы точно находит ноту по клику (pitch + startSec/endSec → `MidiNote` со startTick/endTick); история `Version`-список; «Слушать»/«Сохранить»/ABC работают с `current`.
- **Модель правки — «правка порождает новую Version»** (не мутация выбранной): правленые байты + пересобранные `notes` + старый `report` (или с суффиксом) добавляются в `versions` и выбираются. Тогда откат = выбор предыдущей версии (механизм уже есть) — undo бесплатен в пределах сессии; экспорт/прослушивание не меняются вовсе. В строку версии добавить суффикс-пометку («правка») — поле `edited: Boolean` в `Version` (или текст суффикса).
- **Байтовая правка — по образцу Instruments.kt** (rewriteSample/normalizeMidi): переписываются только события-ноты; дельты: правки высоты/громкости не трогают дельты вообще (1–2 байта на событие); удаление «оплачивает» дельту вперёд (паттерн `droppedDelta` из normalizeMidi); правки времени/длительности требуют перебалансировки дельт соседних событий — отдельная функция.
- **Идентификация событий**: пара NoteOn/NoteOff по (pitch, startTick, endTick) во всех треках (мета-трек с FF 7F не содержит нот — не заденется). Ограничение модели (парсер теряет канал) приемлемо: v2m практически одноголосен; при совпадении нескольких кандидатов правится первый, Log-журнал фиксирует.
- **Фазы**: 1) высота, громкость, удаление (байтово тривиально); 2) сдвиг времени, длительность, вставка ноты/паузы (модель событий с абсолютными тиками, ~100 строк); вставка может использовать клики «мимо» (сейчас бездейственные).

### Вариант 1 — «Клик + панель правки выбранной ноты» (рекомендуется)

**Жест/UI.** Клик по столбику (левая кнопка) — как сейчас: звук тона. Плюс: нота остаётся выбранной (постоянная рамка, не гаснет через 200 мс). Под гистограммой появляется компактная панель (1 строка): `Но́та: D5 · [♭][♯] полутон · [−][+] октава · [−][+] громкость · старт [−][+] / длит. [−][+] (шаг 1/8) · [Удалить] [×]`. Клик по пустому месту или другой столбик — перенос выбора.

**Поток данных.** `hit` (уже есть) → `selectedNote: MidiNote?` → кнопка панели формирует `NoteEdit` (транспонирование/velocity/сдвиг/длина/удаление) → `editNoteMidi(v.midi, edit)` (новая функция ~100 строк в духе Instruments.kt) → `versions += Version(midi', notes', report + "(правка: …)", ...)` → выбор новой. Кнопка [×] снимает выбор без правки.

**Объём.** NoteEdit.kt (~120 строк, фаза 1: высота/громкость/удаление; фаза 2: время), панель в App.kt (~80), состояние + суффикс строки версии (~20). ~220 строк + self-test. Одна новая функция нативной цепочки не нужна — всё в Kotlin.

**Риски.** Аккорды/наложения: правка высоты у одновременной ноты меняет «видимую» лесенку (заливки пересчитываются — ок); правка по (pitch, tick) при двух одинаковых одновременных нотах на разных каналах правит первую — редкий случай, фиксируется в Log. Точность сдвига шагами 1/8 — достаточна «на раз-два-три».

**Совместимость.** Ничего не ломает: хит-тест, звук, экспорт не меняются; добавление — только вокруг. Откат правки — предыдущая версия.

### Вариант 2 — «Контекстное меню правой кнопки» (самый маленький)

**Жест/UI.** Правый клик по столбику — `DropdownMenu` у курсора: «выше на полутон / ниже на полутон / выше на октаву / ниже на октаву / громче / тише / удлинить на 1/8 / укоротить на 1/8 / удалить ноту». Пункт — одно действие, «на раз». Левая кнопка и скролл не затронуты (правый клик сейчас не используется).

**Поток данных.** Тот же, что в варианте 1 (хит → NoteEdit → новая Version), без состояния выбора и панели: меню открывается в точке клика, пункт сразу применяет правку.

**Объём.** Правый-клик-детекция в NoteChart (~15 строк: фильтр кнопки мыши в `awaitEachGesture` — сейчас ловится любая кнопка), DropdownMenu в App.kt (~60), editNoteMidi (~100, фаза 1). ~180 строк. Фаза 2 (время) не входит — меню растёт.

**Риски.** Правый клик «мимо» ноты — не показывать меню (или показывать «вставить паузу…» — фаза 2). Меню на каждое действие — 2 клика (открыть+пункт) против 1 клика кнопки панели; дискретные шаги не дают точных значений.

**Совместимость.** Минимальное вторжение в NoteChart (одно условие кнопки), остальное — как вариант 1. Хорош как первая итерация «попробовать»; панель варианта 1 добавляется позже поверх той же `editNoteMidi`.

### Вариант 3 — «Правый-drag на гистограмме» (жестовый, на потом)

**Жест/UI.** Правый-drag выбранной ноты: вверх/вниз — питч (полутон на ~8 px, показывать текущее имя ноты), вправо/влево от правого края — длительность; Ctrl+колесо — громкость; Del — удалить. Правый-drag не конфликтует со скроллом (скролл — левая кнопка/колесо).

**Поток данных.** Тот же `editNoteMidi`, но серия правок за один жест → одна новая Version по отпусканию (иначе история засоряется). Требует состояния «перетаскиваемой ноты», порогов и индикации — заметно больше кода в NoteChart (детекция жеста поверх хит-теста).

**Объём.** ~300–400 строк + отладка точности (пороги, отрисовка «призрака»). Фаза 2 (дельты времени) обязательна уже в первой итерации — drag без сдвига времени малоинтересен.

**Риски.** Точность попадания в узкие столбики и края; конфликты с будущими жестами; самый дорогой в отладке. Выигрыш — скорость для частых мелких правок.

**Совместимость.** Строится на варианте 1 (выбор + editNoteMidi), не заменяет его; вне первой итерации.

### Сравнение и рекомендация

| | Жесты | Объём | Точность | Откат | Когда |
|---|---|---|---|---|---|
| 1. Панель | клик + кнопка | ~220 | точные шаги, потом поля | версии | **сейчас: основа** |
| 2. Правый клик | 2 клика | ~180 | шаги 1/8 | версии | сейчас: быстрый старт, фаза 1 |
| 3. Drag | правый-drag | ~350+ | грубо, «на глаз» | версии | потом, поверх 1 |

Рекомендация: **начать с варианта 2 (фаза 1: высота/громкость/удаление)** — минимальный код проверяет модель «правка = новая Version» на практике; затем добавить панель выбранной ноты (вариант 1) с теми же `editNoteMidi`, расширив фазу 2 (сдвиг/длительность); drag (вариант 3) — только если А.М. подтвердит необходимость жестового темпа.

Единый новый модуль: `NoteEdit.kt` — `sealed class NoteEdit` + `editNoteMidi(midi, edit)`; Log-строка `[edit]` каждой правки (паттерн `[tap]/[tone]`); self-test: транспонирование/удаление/сдвиг на синтетическом SMF с проверкой через parseMidiSong.
